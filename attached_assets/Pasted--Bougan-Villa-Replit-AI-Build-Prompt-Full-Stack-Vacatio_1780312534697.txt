# Bougan Villa — Replit AI Build Prompt
### Full-Stack Vacation Rental Agency Website + Self-Hosted Property Manager
**Version 1.0 — Architecture Document**

---

## OVERVIEW

Build a complete, production-ready web application for **Bougan Villa**, a boutique vacation rental agency based on the Portuguese coast. The app has two distinct surfaces:

1. **Public Website** — Marketing site for guests to discover and enquire about properties
2. **Admin Panel** — Private, password-protected property management dashboard for the owner

The stack must be simple, free-to-host, and maintainable by a non-developer. No paid services required.

---

## TECH STACK

```
Frontend:       React (Vite) — single repo
Styling:        Tailwind CSS + custom CSS variables
Routing:        React Router v6
Database:       Supabase (free tier) — Postgres + Auth + Storage
Calendar Sync:  iCal parsing (ical.js library)
Email:          EmailJS (free tier) — contact form submissions
Deployment:     Replit (dev) → can export to Netlify/Vercel (free)
Image Storage:  Supabase Storage (free tier: 1GB)
```

**No paid APIs. No Stripe. No external services beyond free tiers.**

## DATABASE SCHEMA (Supabase)

Run these SQL statements in your Supabase SQL editor to set up the database.

### Table: `properties`
```sql
create table properties (
  id uuid primary key default gen_random_uuid(),
  created_at timestamptz default now(),
  name text not null,
  slug text unique not null,           -- URL slug e.g. "villa-bougainvillea"
  type text not null,                  -- 'villa' | 'apartment'
  location text not null,
  region text not null,
  description text,
  short_description text,
  max_guests int default 4,
  bedrooms int default 2,
  bathrooms int default 1,
  tags text[],                         -- ['Pool', 'Garden', 'Beach nearby']
  airbnb_url text,
  booking_url text,
  airbnb_ical_url text,                -- iCal sync URL from Airbnb
  booking_ical_url text,               -- iCal sync URL from Booking.com
  featured_image_url text,
  gallery_images text[],               -- Array of Supabase Storage URLs
  is_active boolean default true,
  display_order int default 0
);
```

### Table: `bookings`
```sql
create table bookings (
  id uuid primary key default gen_random_uuid(),
  created_at timestamptz default now(),
  property_id uuid references properties(id) on delete cascade,
  guest_name text not null,
  guest_email text,
  guest_phone text,
  check_in date not null,
  check_out date not null,
  num_guests int default 1,
  platform text not null,             -- 'airbnb' | 'booking' | 'direct' | 'blocked'
  status text default 'confirmed',    -- 'confirmed' | 'pending' | 'cancelled'
  total_amount numeric(10,2),
  currency text default 'EUR',
  notes text,
  is_manual boolean default false     -- true = entered by owner, false = from iCal
);
```

### Table: `enquiries`
```sql
create table enquiries (
  id uuid primary key default gen_random_uuid(),
  created_at timestamptz default now(),
  name text not null,
  email text not null,
  phone text,
  property_interest text,
  check_in date,
  check_out date,
  num_guests int,
  message text,
  status text default 'new'           -- 'new' | 'replied' | 'closed'
);
```

### Row Level Security (RLS)
```sql
-- Properties: public read, authenticated write
alter table properties enable row level security;
create policy "Public read properties" on properties for select using (true);
create policy "Auth write properties" on properties for all using (auth.role() = 'authenticated');

-- Bookings: authenticated only
alter table bookings enable row level security;
create policy "Auth all bookings" on bookings for all using (auth.role() = 'authenticated');

-- Enquiries: public insert, authenticated read
alter table enquiries enable row level security;
create policy "Public insert enquiries" on enquiries for insert with check (true);
create policy "Auth read enquiries" on enquiries for select using (auth.role() = 'authenticated');
```

### Admin Calendar (`AdminCalendar.jsx`)
Route: `/admin/calendar`

**Unified calendar showing ALL properties and ALL bookings:**

- Month view (default) with previous/next navigation
- Property filter dropdown (All / Villa Bougainvillea / Apartamento São Martinho)
- Platform filter (All / Airbnb / Booking.com / Direct / Blocked)

**Colour legend:**
- 🟥 Airbnb booking (red)
- 🟦 Booking.com booking (blue)
- 🟩 Direct booking (green)
- ⬛ Owner blocked / maintenance (grey)

**Calendar data sources (merged):**
1. `bookings` table in Supabase (manual + imported entries)
2. iCal URLs fetched live from `properties.airbnb_ical_url` and `properties.booking_ical_url`

**iCal sync logic (`src/lib/ical.js`):**
```
- Fetch iCal URL via proxy (CORS issue — see note below)
- Parse using ical.js library
- Extract VEVENT blocks: DTSTART, DTEND, SUMMARY
- Map to a normalised booking object: { source, property_id, check_in, check_out, summary }
- Cache in localStorage with 15-minute TTL
- Merge with Supabase bookings, deduplicating by date range
```

> **CORS Note:** Airbnb and Booking.com iCal URLs block direct browser fetch due to CORS. 
> Solution: Use a Replit Express backend endpoint `/api/ical-proxy?url=ENCODED_URL` that 
> server-side fetches the iCal and returns the raw text. This proxy is part of the same 
> Replit project (full-stack).

**Click on a day:** shows a popover with bookings that day + option to add a manual booking.

**"Sync Now" button:** re-fetches all iCal URLs and refreshes the view.

## ICAL PROXY BACKEND (Express)

Since this is a full-stack Replit, add a minimal Express server for the iCal proxy:

```javascript
// server.js
import express from 'express'
import fetch from 'node-fetch'
import cors from 'cors'

const app = express()
app.use(cors({ origin: true }))

app.get('/api/ical-proxy', async (req, res) => {
  const { url } = req.query
  if (!url) return res.status(400).json({ error: 'url param required' })
  
  try {
    const response = await fetch(decodeURIComponent(url), {
      headers: { 'User-Agent': 'BouganVilla/1.0' }
    })
    const text = await response.text()
    res.set('Content-Type', 'text/calendar')
    res.send(text)
  } catch (err) {
    res.status(500).json({ error: 'Failed to fetch iCal', detail: err.message })
  }
})

app.listen(3001, () => console.log('iCal proxy running on :3001'))
```

The Vite frontend proxies `/api` to `:3001` in `vite.config.js`:

```javascript
export default {
  server: {
    proxy: {
      '/api': 'http://localhost:3001'
    }
  }
}
```

## IMAGE HANDLING

All images are stored in **Supabase Storage** in a public bucket called `property-images`.

**Admin upload flow:**
1. Owner selects image file(s) in admin panel
2. App uploads to Supabase Storage: `property-images/{property_slug}/{filename}`
3. Supabase returns a public URL
4. URL saved to `properties.featured_image_url` or appended to `properties.gallery_images[]`

**Public placeholder images:**
Until real photos are uploaded, display a styled placeholder div:

```jsx
// In PropertyCard.jsx
{property.featured_image_url ? (
  <img src={property.featured_image_url} alt={property.name} />
) : (

  <div className="photo-placeholder">
    <span>{property.name}</span>
    <small>Photo coming soon</small>
  </div>
)}
```

## SECURITY NOTES

- Supabase RLS policies enforce that booking/enquiry data is auth-protected
- The admin login uses Supabase Auth (bcrypt-hashed passwords, JWT sessions)
- The iCal proxy only fetches URLs starting with known hosts (airbnb.com, booking.com) — add a whitelist check
- `.env` file must be in `.gitignore` — never commit keys
- Images in Supabase Storage are in a **public** bucket (acceptable for property photos)
